# Hirari と Cubase Pro 15 の到達度ロードマップ

## 比較の基準

このロードマップでは Steinberg が公開している Cubase Pro 15 を機能基準にする。
比較対象は機能名ではなく、利用者が画面から操作し、結果を保存し、再読込後も
同じ結果を得られる制作工程とする。エンジン API や capability 宣言だけの機能は
「利用可能」と数えない。

段階は次のように区別する。

- **画面から完結**: UI 操作、保存、再読込まで確認できる。
- **エンジン契約のみ**: API や内部実装はあるが、UI の制作工程が未確認。
- **未実装**: 利用者向けの機能がない、または代替操作がない。
- **外部検証待ち**: 対応コードはあるが、実機、SDK、第三者製品での証拠がない。

現時点の資料からは、Hirari は Cubase と同等の完成度には達していない。
README が列挙する技術プレビューの制約に加え、旧C++ UI資産とRust/Slint `hirari-ui` の
関係を明確にする必要があった。Gitのベースリビジョンには既に製品UIクレートがあり、現在の
作業ツリーで `hirari-ui` へ改名しているため、今回UI一式を新設したわけではない。ルートの `src` は
C++エンジン資産である。現行アプリはCargo
ワークスペースの `hirari-ui` が起動し、`hirari-core-bridge/build.rs` は `src/core` と
`src`直下のC++実装を橋渡し用にビルドする。グラフィックス実装とネイティブ契約テストが使う
C++補助ヘッダーは `src/graphics/ui_components/support` へ移し、旧C++ウィンドウ・workspace
コードを `archive/legacy-cpp-ui` へ退避した。Rust/Slintの実製品UIとC++エンジンの責務を
コード配置でも表す一方、
最初にRust UIを独立クレート化した設計経緯や、旧UI資産を残した理由はGit履歴・設計資料に
記録されていない。

## 2026-09-25 実装到達判定とロードマップ改訂

旧P0（画面操作の実接続）と旧P1（録音・編集・保存・再開・書き出し）の
主要な実装群は到達した。ここで「到達」は、記録した機能のコード経路を接続した
という意味で、全工程の実機検証やCubase Proとの同等性を意味しない。
旧P0/P1の細かな実装記録は各章末尾に履歴として残し、これからの優先順位を
次のP0/P1へ更新する。新しいP0/P1はプロジェクト破損防止と大規模制作の応答性を
対象とし、実装の残りを検証作業だけに置き換えない。

## Hirari 自身の到達目標

### P0 — プロジェクトを壊さず保存・移行・復旧できる

**この改訂での状態:** コード実装は完了扱い。欠損素材は明示的な再リンクを求め、freeze/OpenUtauは保存済みchecksumが一致しない置換を拒否する。読込またはUI hydrationが失敗した場合はCore/UIをrollbackし、再リンクで先に更新したプロジェクトファイルも元のbytesへ戻して旧世代を保持する。通常保存と移行は世代バックアップ付きatomic writeを通し、パッケージ復元は検証・一時展開・同期後に公開する。故障注入と実機確認は未実施で、製品保証済みを意味しない。

- **保存世代と移行を原子的に扱う:** canonical `ProjectDocument`を単一の状態源とし、旧JSON/native sidecarの読込は明示的な移行経路へ閉じ込める。移行中に一部データだけを書き換えず、入力世代・変換結果・公開先を分け、完全検証後にだけ新世代を確定する。失敗時は旧世代をそのまま開ける。
- **素材欠損を修復可能にする:** 読込時に欠損/移動した音声・freeze・OpenUtau素材を識別する。通常音声は利用者がファイルを明示選択し、freeze/OpenUtauは保存済みchecksumが一致した場合だけ再リンクする。解決できない参照は読込を拒否し、無音の部分読込を成功扱いにしない。
- **復旧をCore/UI/ファイルで一体化する:** Core checkpoint、staged UI model、保存世代を同じproject generationに結び付ける。Core復元・UI再水和・復旧ファイル公開のどこかが失敗した場合に、UIだけ新状態になることや復旧元を上書きすることを防ぐ。現在のUI stagingとCore rollbackを、この世代契約へ拡張する。
- **持ち運びパッケージの復元後に独立させる:** `.hirari-package`はmanifest検証済みの素材を含むが、復元先で元プロジェクトを参照し続けないこと、既存プロジェクトとの衝突時に上書きしないこと、復元失敗で部分公開しないことを実装契約として固定する。
- **実装済みの範囲:** 通常のOpen経路で参照切れの音声・freeze・OpenUtau素材を一覧化し、ファイル選択で再リンクする。freezeとOpenUtauはストリームSHA-256が既存checksumと一致する場合だけ採用し、更新したプロジェクトは通常の世代バックアップ付き保存を通す。Core/UI loadまたはhydrationが失敗した場合は、再リンク前のproject bytesも世代バックアップ付きで復元する。パッケージのファイル/ディレクトリ公開前に内容と配下ディレクトリを同期し、rename後に親ディレクトリも同期する。UI/Core bridgeのcargo checkは成功。ダイアログの実操作、誤ファイル選択、キャンセル、保存再読込、電源断耐性は未確認。
- **完了条件（コード）:** 旧形式からの移行・保存世代切替・素材再リンク・パッケージ復元・Core/UI rollbackが、成功時に同一世代を開き、失敗時に直前の正常世代を保持するコード経路を備えた。故障注入・実機・実ファイル往復の合格は別の受入検証として残す。
