# Rust migration equivalence gates

A successful build only proves that both sides compile. It does not show that a
Rust replacement preserves the old engine's audio or event behavior. Do not
remove a working C++ implementation as part of a DSP migration until a frozen
C++ reference and a differential test cover the behavior being replaced.

## Current differential fixtures

The reference implementation is test-only and compiles only when the
`dsp-differential-reference` Cargo feature is enabled. Run the focused checks
with:

The sampler and rendered STFT/OLA comparisons use a `2e-5` and `8e-5`
absolute error limit respectively and check finite-value classification
separately. The raw FFT forward-bin limit is `2e-3 + 2e-4 * |reference|` to
account for accumulated f32 butterfly rounding on large plans; inverse output
must remain within `3e-5`. If a tolerance changes, retain the worst-case
fixture and explain why the numerical difference is acceptable. Keep at least
one short block, one non-hop-aligned block, and one long block around every
stateful streaming transition.

## Migration completion rule

A component is not marked migrated when only the Rust build passes. Its
replacement gate must include the same PCM/MIDI fixtures through the C++
reference and Rust path, output comparison, state-transition coverage, invalid
input handling, and channel/block-boundary cases. Keep uncovered behavior
explicitly listed here; passing one operation does not qualify the whole DSP
component as equivalent.
